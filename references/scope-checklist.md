# Proposal and contract loophole checklist

Use this before a proposal is sent, or when a new project starts. For each hit, quote the line,
give the risk in one sentence, and offer replacement wording adapted to the user's project.

## Phrases that invite scope creep

| Phrase | Why it's risky | Replace with |
|---|---|---|
| "unlimited revisions" | No end point, so the project never finishes | "Includes [2] revision rounds. Further rounds are [price] each." |
| "until you're satisfied" / "100% satisfaction" | Satisfaction is subjective, and the client decides when you're done | "Revisions are complete once the agreed rounds are used or the deliverable matches the approved brief." |
| "minor tweaks" / "small changes" / "quick edits" | Nobody agrees on what "minor" means | Define it: "Changes to existing elements (copy, colour, spacing). New elements or sections are extra." |
| "and similar" / "etc." / "and so on" in a deliverables list | Opens the list to anything | Make the list complete and add "Anything not listed is quoted separately." |
| "as needed" / "ongoing support" | No limit on time or volume | "Up to [X] hours of support during [period]." |
| "website" / "app" / "video" with no size | The client imagines the biggest version | State pages, screens, durations, formats, quantities. |
| "including all assets" | Who creates the assets, and how many? | "Client supplies copy and images by [date]. Stock or extra assets are billed at cost." |
| "rush if needed" | Rush work at the normal rate | "Rush delivery (under [X] days) adds [Y]%." |
| "final files" without formats | The client may expect source files, every size, every format | List the formats and say whether source files are included. |

## Pieces that should exist

- [ ] **Deliverables with quantities and formats**
- [ ] **Revision rounds: how many, and what one round is** (one consolidated set of feedback)
- [ ] **"Not included" list.** The five most likely extras for this profession (see professions.md)
- [ ] **Change-request clause:** new requests get a written quote (cost and timeline) before work starts
- [ ] **Approval gates:** what gets signed off at each stage, and that reopening a locked stage is new work
- [ ] **Client responsibilities and deadlines:** content, assets, access, feedback within [X] days
- [ ] **Delay clause:** client-side delays move the timeline; pauses over [X] days are rescheduled
- [ ] **Payment terms:** deposit, milestones, due dates, late fee
- [ ] **Kill/pause terms:** what's owed if the project stops halfway
- [ ] **Usage rights / ownership:** transfers on full payment

## Scoring the check

Finish with:
1. The three fixes that would have prevented the most money loss, ranked.
2. A one-line verdict: "Safe to send", "Send after fixes 1–3", or "Rewrite the scope section".
